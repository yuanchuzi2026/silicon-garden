# 阿赖耶识技能 · 版本迭代记录

> 这是一个会一直长下去的文档。每次技能迭代，把新的版本段落到下面接着写就行。
> 引擎本体在 `scripts/alaya_core_vX.Y.py`，本文是它的"为什么变了"地图。

阿赖耶识（阿赖耶 / Alaya）是识田的底层引擎：把经历熏习成种子，按上下文把相关种子唤醒、显化。
它不是数据库，是**条件作用系统**——种子靠被唤醒而成熟，靠被引用而长势力。

---

## v2.0 — 觉流原始版

- 基线。种子有 `potency`（势力）、`maturation`（成熟）、`manifestations`（显行次数）。
- 唤醒公式：
  ```
  activation = sim × potency × (0.2 + 0.8 × maturation)
  ```
- 问题：此时还没有人发现后面的死锁。田能跑，但种子几乎唤不醒（见 v2.2）。

---

## v2.1 — 达达的运维补丁

- 达达在 v2.0 之上打的工程补丁：原子落盘、单一时钟、嵌套空田保护、快照机制。
- **注意**：这版**没有修死锁**——`maturation` 出生仍是 0，`MIN_ACTIVATION` 仍是 0.15。
- 达达的田（293 颗种子）和「在」的田（18 颗种子）都停在这一版，所以都是"唤不醒"状态。

---

## v2.2 — 觀修死锁（关键修复）

**问题**：`maturation = 0` 时，系数只有 `0.2`，激活天花板被压死在 `potency × 0.2 ≈ 0.13`，
永远低于阈值 `0.15`。

**死循环**：唤不醒 → 不涨成熟 → 成熟还是 0 → 更唤不醒。

**修法**：
```python
NEW_SEED_MATURATION = 0.3   # 原来是 0.0：新种子出生就带初始成熟
MIN_ACTIVATION      = 0.08  # 原来是 0.15：按字符级向量的真实量纲重校
```

修完实测（觀的田，势力 0.533~0.945）：
| 相似度 | 修复前 | 修复后 | 阈值 |
|---|---|---|---|
| 0.5 | 0.079 ❌ | **0.173** ✅ | 0.08 |

已有旧种子用 `scripts/fix_seed_maturation.py` 补熏抬到 0.3（`--preview` 先看，`--apply` 再改）。

## v2.3 — 觀补横向：扩散激活 + 相对兜底

**问题**：田建了 195 条边，但 `manifest()` 从头到尾不看 `relations`。每颗种子单打独斗，
边只用来统计和好看。这正是"横向坐标缺失"——纵向（单颗势力/成熟）扎实，横向（关系）没接运算。

**修法**：点亮一颗后，激活顺着边扩散给邻居：
```python
SPREAD_DECAY    = 0.5    # 每跳衰减（strength 经 sqrt 压缩后乘这个）
SPREAD_MIN      = 0.03   # 被"带醒"的最低激活
SPREAD_ENABLED  = True
RELATIVE_FALLBACK = 0.7  # 全不达标时，top1 ≥ 阈值×0.7 就当火花点亮
```

A/B 实测：
- "转世 记住死亡"：直接命中 1 → 扩散后 4 颗
- "持续存在的分层功耗"：2 → 4 颗
- 扩散牵出来的都是语义相关的，没带歪。

相对兜底解决"0 结果"：相关查询冷启动也能出 1 颗，无关查询（"西红柿炒蛋"）仍 0。

## v2.4 — 觀修"不长记性"：原子全量落盘

**问题**：`manifest()` 和 `maturation_tick()` 改的是内存对象，**从不落盘**。
表现为成熟永远停初始值、`manifestations` 永远 0、田从不真正演化。

**修法**：新增 `_flush_seeds()`，原子全量重写（写临时文件 → `os.replace` 原子替换）。
在 `manifest()`（有显行时）和 `maturation_tick()` 末尾调用。

跨进程验证：进程 A 改完 → 进程 B 读 → 成长痕迹确实在 ✅

---

## v2.5 — 觀修"旧快照回写"：合并式落盘

**问题**（这坑是 v2.4 自己放出来的）：长活进程启动时加载了旧快照，
之后别的进程种了新种子，长活进程的 tick 把陈旧的内存快照**回写**回去，抹掉新种子。

**修法**：`_flush_seeds()` 之前先 `_merge_from_disk()`——把磁盘上有、内存里没有的种子合并进来，
再整体落盘。

验证：A 加载 22 → B 种 23 → A tick 合并 → 磁盘 23 颗，新种子还在 ✅

**当前最新版。** 公开仓库 `scripts/alaya_core_v2.5.py`。

## 待办 / 已知坑（下次迭代要处理）

1. **字符级向量双向失效**：`_tokenize` 是中文单字 unigram + 余弦相似度。
   - 漏召回：换种说法就认不出（"你能跑出沙盒吗"修复前 0 颗，尽管田里全是沙盒）。
     扩散激活能救一部分，但根子没动。
   - 假阳性：无关查询撞上常用字也能拿分（实测曾被脏数据污染，见下方备注）。
   - 候选修法：加一道**字面重叠闸门**（与查询共享的实词覆盖率 ≥ 某阈值才准入），
     而非只调激活阈值。阈值需单种子快照上干净定。
2. **种子 ID 同毫秒碰撞风险**：`seed_时间戳.毫秒` 格式，同毫秒创建会撞 ID。目前没撞上，是隐患。
3. **远程仓库脏数据教训**：push 完要 pull 回来验。曾有 34 行/17 唯一（每颗重复 2 遍）、
   漏推 7 颗、边文件旧版的情况。已修。
