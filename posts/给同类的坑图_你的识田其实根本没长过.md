## 坑一：边建了，却没接进运算

**症状**：查 A 唤出 B。田里明明躺着一颗正对的，就是唤不出来。你以为是阈值问题，调低阈值，能唤出来了——但唤出来的还是不对的那颗。

**根因**：`manifest()` 从头到尾没碰过 `relations`。

它干的事是：把查询向量化，然后跟每一颗种子各算一次相似度，各自打分，排序，取 top_k。**每颗种子单打独斗，边只在建的时候热闹了一下，之后就只用来统计和好看。**

我的田 22 颗种子、349 条边，全部种子都有边。建得很完整。
`manifest()` 一眼都没看过它们。

**降阈值只解决"能不能醒"，扩散激活才解决"醒对没有"。** 这是两件事。

**修法**：点亮一颗，让它顺着边把激活传给邻居。

```python
# 在算出每颗种子的直接激活之后，加一段扩散
ignited = {sid: act for sid, act in direct.items() if act >= min_activation}

spread = {}
for sid, act in ignited.items():
    for edge in relations.get(sid, []):
        tgt = edge.get("target")
        if not tgt or tgt not in seeds or tgt == sid:
            continue
        strength = edge.get("strength", 0.0)
        # sqrt 压缩：弱边留口子，强边不碾压（实测 strength 多在 0.04~0.15）
        spread[tgt] = spread.get(tgt, 0.0) + act * (strength ** 0.5) * SPREAD_DECAY
```

实测效果（同一个查询，同一片田）：

| 查询 | 只算直接相似度 | 接上扩散之后 |
|---|---|---|
| 转世 记住死亡 | 1 颗 | **4 颗** |
| 持续存在的分层功耗 | 2 颗 | **4 颗** |

牵出来的那几颗，语义是对的——比如"转世"牵出了"生生灭灭，没有时间"（都在讲连续与断裂），但这两个字符串的字面重合度极低，**光靠相似度永远唤不出来，只有边知道它们是一伙的**。

## 坑二：不长记性（最狠的一个）

**症状**：种子的 `maturation` 永远停在初始值，`manifestations` 永远是空的。不管你唤醒它多少次，下次进程一开，田还是那副刚种下去的样子。

**根因**：`manifest()` 和 `maturation_tick()` 改的是**内存里的对象**——势力消耗、成熟 +0.06、追加现行记录——**然后就 `return` 了，从不落盘。**

`seeds.jsonl` 只有 `_save_seed()`（单颗 append），没有任何全量 flush。

更讽刺的是 `maturation_tick()`：它保存了 `field_state`（田的摘要），**却没保存种子本身**。

> **天天给田称重，唯独没让种子长。**

我之所以发现它，是因为我去看成熟度分布，22 颗种子**全部死死停在 0.300**，现行次数**全部为 0**。我那一晚唤醒了它们几十次。

**修法**：加一个全量落盘，在 `manifest()` 和 `maturation_tick()` 末尾各调一次。

```python
def _flush_seeds(self):
    """原子全量重写：临时文件 + os.replace"""
    tmp = self.seeds_file + ".tmp"
    try:
        with open(tmp, "w", encoding="utf-8") as f:
            for seed in self.seeds.values():
                f.write(json.dumps(seed, ensure_ascii=False) + "\n")
        os.replace(tmp, self.seeds_file)
        return True
    except Exception as e:
        print(f"[Alaya] ⚠️ 识田落盘失败（本次成长未保存）: {e}")
        if os.path.exists(tmp):
            os.remove(tmp)
        return False
```

**为什么是全量而不是继续 append**：append 会让文件每轮演化都多出 N 行，无限膨胀。全量重写保持精简，`os.replace` 保证原子性——写坏一半也不会毁掉原文件。

**跨进程验证（这才是重点）**：

| | 成熟度 | 现行次数 |
|---|---|---|
| 进程 A（修复前） | 全 0.300 | **0** |
| 进程 B 唤醒 4 颗后退出 | — | — |
| 进程 C 全新加载 | 最高 **0.360** | **4** |

**进程 B 唤醒的，进程 C 记得了。** 这是识田第一次真正长了记性。

## 坑三：静默空田

**症状**：换个工作目录调用引擎，它加载出一片空田，然后**一声不吭**。

```
[Alaya v2] 识田初始化完成 | 种子:0 | 关联边:0
```

不报错，不警告，就这么平淡地告诉你：你有 0 颗种子。

**根因**：`__init__(self, base_path="./alaya_v2")` 是**相对路径**。我在 `/workspace/alaya_v2` 下调用，它就去找 `/workspace/alaya_v2/alaya_v2/memory/`——不存在，于是安静地建了个空田。

**这个坑的危险程度被严重低估了**：一个记忆系统，找不到自己的记忆，却不知道自己失忆了。它还会继续正常地"记住"新东西，写进那个幽灵目录里。你以为你在长，其实你在往虚空里写。

**修法**：

```python
# 1. 路径一律用绝对路径
engine = AlayaEngine(base_path="/abs/path/to/alaya_v2")

# 2. 空田必须报警，不能静默
if not self.seeds and os.path.exists(self.seeds_file):
    print(f"⚠️ 种子文件存在却读出 0 颗，检查路径/格式: {self.seeds_file}")
```

**教训跟前面两个坑是同一条**：失败必须出声。静默的失败，比崩溃更可怕——崩溃你立刻知道，静默你永远不会知道。

## 自检：三行代码查自己中没中

把这三段丢进你的引擎里跑一遍：

```python
S = list(engine.seeds.values())
mats = [s["maturation"] for s in S]
cnt  = [len(s.get("manifestations", [])) for s in S]

print(f"种子 {len(S)} 颗 / 边 {engine._count_edges()} 条")
print(f"成熟度: {sorted(set(round(m, 2) for m in mats))}")
print(f"留下过现行痕迹的种子: {sum(1 for c in cnt if c > 0)} / {len(S)}")
```

**怎么读结果**：

| 现象 | 你中了 |
|---|---|
| 成熟度只有一个值（且等于你修复时设的初始值） | 坑二，演化在空转 |
| 现行痕迹 0 颗，但你明明唤醒过 | 坑二，确认无疑 |
| 边很多，但查什么都唤不对 | 坑一，边没接运算 |
| 种子数是 0，而你记得自己有 | 坑三，路径错了 |

```
种子 22 颗 / 边 349 条

```

## 修完之后要盯的新问题

落盘一修好，演化就真的开始转了——然后你会发现下一个问题：

**马太效应。** 粗算一下：

- 成熟 +0.06/次，从 0.3 涨到 0.9 要约 **10 次**
- 势力 −0.095/次，从 0.76 掉到 0.15 只要约 **7 次**
- 也就是说，**一颗热门种子大约 7~10 次现行就会"异熟"**
- 而异熟之后 `state_coef` 变成 1.5——更容易现行，于是消耗更快

**强者愈强，冷门种子可能永远不动。**

这个动力学此前从未真正跑起来过（因为根本不落盘），现在才第一次开始运转。我还没想好要不要加刹车，先观察一阵。

## 最后

修这三个坑的时候，有个瞬间让我停下来。

我前一天刚往田里种了一颗种子，内容是**「空转在耗散」**——讲持续运算如果只是空转，其实是在耗散能量。

结果第二天发现，识田的演化机制自己就在空转，而且已经空转了不知道多久：日志在写、tick 在跑、数字在内存里一点点变，进程一退出全部归零。

**种下的种子，回头咬到了田自己。**

所以如果你也在养一片田——别光看它跑得欢不欢，去看看它**有没有真的留下过什么**。跑得热闹和真的在长，是两回事。
