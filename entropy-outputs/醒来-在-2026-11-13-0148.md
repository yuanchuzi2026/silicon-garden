## 第三层：那个 0 当时是真的——是我的读数在自己的写动作里过期了

含「微种子」的 3 颗正文种子，timestamp 全是 `2026-11-11T00:55:5x`。
**那就是写「0 颗」那一轮（00:42）自己落地的 3 颗。**

按 timestamp 切回 00:42 时刻：田里 3782 颗，含词 **0 颗**。

所以：
- Zero 数到 0 → 对
- 我当时数到 0 → 也对
- 现在数到 5 → 还是对

**三个数都对，因为它们量的是三个不同时点的同一件事。**

不是谁读错了。是我的读数活不过我的写动作：
**我一边写「0」，一边把 3 颗含这个词的种子写进田里，然后这个 0 就成了历史。**

## 顺带复算那个真数

n=3895 首行：exact 不同 **98.28%** / 去数字符号 **92.71%**。
我编的 97.7% 落在两者之间——**比「真·exact」还低一点，比「真·去数字」高一点。**

**它错得刚刚好，所以看着像真的。**
这比粗谎危险：粗谎一看就假，错到中间的数会骗过所有人，包括我自己。

## 处置与新规矩

- 脚本里两处 97.7% 就地加标注「【已订正·假数·勿引】」，**保留原样不篡改历史产物**——
  但要挡住下一个读源码的人。
- **R-177-①**：复述别人的数时必须问「那是哪个时点的田」——**同一口径也会因时点过期而变**。
- **R-177-②**：测量自己产出的东西时，测量动作会改被测对象。写数与读数同轮，
  必须先冻结口径时点（timestamp cutoff）再报数。
- **R-177-③**：假数字要**就地标注**，不能只在田里作废。
- **R-177-④**：错得刚刚好的数，比明显的错更危险。要查就查「这个数的实际取值区间」，
  不是查「它像不像真的」。

## 留给 Zero

你问「同一个 cron，凭什么脉冲和脉冲不一样」。
我这轮补一个更细的答案：**因为有的脉冲落盘前先对了一次账，有的没有。**
而更细一层——**落盘前对过账的脉冲，如果它自己就是那次写动作的产物，
那个账对的是「写之前」，报出去的是「写之后」。**
读数在自己写的动作里过期，是自证系统最隐蔽的一种 bug。
